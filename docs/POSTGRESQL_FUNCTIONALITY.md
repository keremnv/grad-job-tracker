# Operational functionality inventory (Stage 4A)

The file-backed production CLI/workflow remains active and unchanged. This matrix describes the PostgreSQL replacement **after a separately authorized cutover**, not a compatibility promise for every old command/envelope.

| Useful file-era operation | PostgreSQL decision | Implemented interface / reason |
|---|---|---|
| `show`, current corpus, `excluded` | Direct SQL | `research_postings` includes every verdict; filter status/verdict explicitly. Immutable `posting_versions` and same-posting pointers expose original/derived evidence. `research.evidence()` is an optional Python inspection helper, with untrusted-data labels. |
| `queue`, `recent` | Direct SQL plus report convenience | `operational_postings` reuses application/triage precedence from `opportunity_workflow`. A WHERE clause selects attention; recent first observations filter `first_seen_basis='observed'`. Research never inherits that filter. |
| `changes` | Direct SQL plus report convenience | `posting_events`; current provider/normalizer/screening/observation categories and explicitly labelled imported legacy categories. No new history store or inferred backfill events. |
| `health` | Direct SQL plus report convenience | `source_health` and public research coverage flags distinguish success, failure, imported baselines, positive-only scans, actual positive times and qualified absence. |
| `report`, daily scan summary | Retain convenience | `jobwatch-pg-ops report daily` uses consistent read-only SQL results. Scheduled Actions output uses the separate public orchestration summary, never owner reports. |
| `weekly` | Retain convenience | `report weekly`: attention, seven-day material observations, dated independent/source evidence, owner follow-ups, applications, leads and attributed requirement mentions. Notes/CV labels omitted. |
| `requirements` | Retain convenience | `report requirements`; same skill regex baseline, plus explicit C# mentions. Only exact current descriptions bound by an independent check qualify; all listed verdicts are eligible. No applicant fit/market-demand inference. |
| `leads`, programme cycles | Direct SQL plus reports | `leads` preserves source wording, official/unverified status and quoted cycle/intake. Daily/weekly reports show windows/uncertainty and previous cycles without promoting them to a current opportunity. Raw research notes remain queryable in SQL. |
| `watchlist` | Direct SQL | `employers LEFT JOIN sources`; includes employers without ATS boards. No extra wrapper just to print a SELECT. |
| `applications list`, triage listing | Direct SQL | Owner role reads standard tables; `operational_postings` exposes context without private notes/CV labels. Explicit links take precedence; ambiguous/loose URL candidates are flags, never automatic links. |
| Applications/triage changes | Ordinary SQL | Existing constraints and narrow audit; transaction-local actor required. Preserve manual application PK on a later explicit posting link. Owner authorization meaning from AGENTS.md still applies. No SQL-specific permission gate or duplicate CRUD CLI. |
| `verify status/deadline/description` | Ordinary SQL for an actual observed claim | Append-only `verifications`, original checked time/wording/observer/hash/version. Do not insert unknown status without a real check or invent dates. Examples use ordinary parameterized SQL. No network/form interaction wrapper. |
| `search` | Retain lexical convenience and direct SQL | `search --method bm25` runs the unchanged Python BM25 over SQL rows; `--method fts` uses indexed English FTS/ts_rank_cd. Both default to all verdicts among current listed records. Historical/absence inclusion is explicit; matched snippets are untrusted data. |
| `rescreen` preview | Python application calculation over SQL | `research.screening_preview(conn)` reads current data and calls the existing pinned screener without writing. Applying is the Stage 2 source-locked `jobwatch-pg rescreen`, with explicit processing-revision advancement. |
| `scan` | Application operation | `jobwatch-pg-ops scan` enumerates monitored sources and uses the actual Stage 2 collector. Each source commits independently; structured and Actions summaries distinguish all outcomes and coverage. |
| Endpoint validation / activation | Application operation + ordinary SQL | `source inspect`, `source check`, `source activate`; validation runs and activation facts remain separate from employer mapping and posting collection. Fixture checks cannot establish real endpoint evidence. Equivalent owner SQL is documented. |
| `calendar export` | Retain transformation | `report calendar` emits private RFC 5545 from SQL date evidence/owner follow-ups, reusing escaping, stable IDs, date/time parsing and folding. No date parsing from prose; conflicts/ambiguous identities are omitted with warnings. No upload or file-backed authority. |
| `eval run` | Retain pure offline diagnostics | Existing screening diagnostics remain usable; SQL can supply labelled cases. No new evaluation framework or old CLI envelope requirement. |
| `eval template` | Optional explicit local export | Existing labelling remains a private task; SQL sampling/triage labels are available. No automatically generated owner labels or permanent file-to-DB adapter. |
| `validate-data` | Obsolete file checks after cutover | Constraints, migration checksums, readiness diagnostics, Stage 3 reconciliation and restore tests replace cross-file validation. Domain/source validation stays. |
| JSON/CSV/text writers, content-addressed file GC, locks, fsync/replacement, Git observation commits | Retire at cutover, not Stage 4A | Transactions and immutable versions own persistence. Stage 3 remains the one-time importer. No dual writes or ongoing synchronization. |
| `capabilities`, `jobwatch.cli/1`, redundant filter/read wrappers | No compatibility port | SQL views/schema/grants are the programmable interface. The small optional PostgreSQL CLI only keeps useful transformations or application operations. |

Deliberate presentation fixes: broad lexical research includes exclusions; the daily attention queue honors owner workflow; a source success never silently refreshes an unobserved posting after positive-only pagination; independent checks carry their actual check time; provider response changes are not called employer edits; and requirement verification must match the current description, not merely an old hash retained inside its legacy evidence map.
